# Google and Apple sign-in

Pinkas uses Supabase for browser authentication. The login and registration pages offer Google and Apple alongside email. Social sign-in uses a PKCE verifier stored in the initiating tab, an exact callback URL, and a one-time authorization code. Supabase creates or resolves the user. Pinkas stores the Supabase session through the existing client and restores the requested page. Email confirmation and recovery still use their existing links.

## Activate the providers

- **Supabase**. Set the production Site URL to `https://pinkasapp.com` and add `https://pinkasapp.com/auth/callback` to Authentication → URL Configuration → Redirect URLs. Keep the existing recovery and confirmation URLs. Use a separate project or exact additional URL for a staging environment. [Supabase redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls)
- **Google**. Create or reuse Pinkas's Web application OAuth client. Use the Pinkas origin `https://pinkasapp.com` and the callback shown by Supabase for Google, which ends with `/auth/v1/callback`. Enter the client ID and secret in Supabase Authentication → Sign In / Providers → Google. If the OAuth app is in Testing, use an explicitly listed test user during verification. For a public release, configure consent branding and the privacy-policy link on the verified Pinkas domain. [Supabase Google setup](https://supabase.com/docs/guides/auth/social-sign-in/auth-google) · [Google verification requirements](https://support.google.com/cloud/answer/13464321?hl=en)
- **Apple**. Use Apple Developer's website configuration for a Services ID associated with the Sign in with Apple-enabled primary App ID. Register the return URL shown by Supabase, generate the Apple client secret with the signing key, and configure the Services ID and secret in Supabase. Renew the client secret before it expires (Apple allows up to six months). Verify both Share My Email and Hide My Email on an existing test account as applicable. [Apple web configuration](https://developer.apple.com/help/account/capabilities/configure-sign-in-with-apple-for-the-web) · [Supabase Apple setup and secret rotation](https://supabase.com/docs/guides/auth/social-sign-in/auth-apple)

Store provider credentials in Supabase. The frontend only needs the existing public Supabase URL and publishable key. Supabase links eligible identities with the same verified email. An Apple relay address can be a different identity, so test that case separately and avoid assuming it should resolve to an existing Pinkas account. [Supabase identity linking](https://supabase.com/docs/guides/auth/auth-identity-linking)

## Verify a release

- Run frontend type checking, the production build and Vitest. The Playwright suite exercises the email forms and simulated OAuth on desktop Chromium, mobile Chromium, and iPhone-sized WebKit. It covers a successful callback, redirect to a protected link, consent cancellation, a failed exchange and a missing local attempt.
- After enabling each provider, verify a real sign-in and a fresh registration on the deployed domain. Test cancellation and retries, verify the existing email password-recovery flow, and ensure the correct account's transactions load. On a physical iPhone, test both Safari and the installed web app if it is in use.
- Inspect keyboard navigation, focus and announcements for sign-in errors, password manager autofill, and Hebrew layout at common narrow widths. Verify a representative transaction edit round-trip and bank-refresh error recovery after changes that touch those flows. [WCAG accessible authentication](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html)
- Measure the public home page, sign-in page, and first dashboard on realistic devices and connections. Track 75th-percentile LCP ≤2.5 s, INP ≤200 ms and CLS ≤0.1 on mobile and desktop. Local measurements can reveal regressions. Real-user data is needed to establish percentile performance. [Core Web Vitals](https://web.dev/articles/vitals)

Provider artwork comes from the official [Google identity branding assets](https://developers.google.com/identity/branding-guidelines) and [Apple button API](https://developer.apple.com/documentation/signinwithapplerestapi/get-a-sign-in-with-apple-button-that-contains-just-the-apple-logo.).
